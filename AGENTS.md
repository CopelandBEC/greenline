# Greenline

Lean native PDF markup app for senior review of drawings/specs/decks (Rust, egui + PDFium). Renamed from Redline in 1.3: the data dir is migrated on first launch (`sidecar::dir`) and the installer keeps the old AppId and clears Redline's leftovers.

- Targets Linux and Windows (1.0+). `scripts/fetch-pdfium.sh` downloads `libpdfium.so` / `pdfium.dll` (Git Bash) into `vendor/` (gitignored); the binary finds it next to itself, in `vendor/`, `~/.local/lib`, or `/usr/lib`. Cross-check Windows code locally with `cargo check --target x86_64-pc-windows-gnu`.
- Platform specifics live behind `cfg(windows)`: font candidates (`fonts.rs`: Liberation/Noto on Linux, Arial/Segoe on Windows; the first must be Helvetica-metric), data dir (`sidecar::dir`), default author name. Paths are canonicalised with `dunce` (no `\\?\` prefixes).
- Release: CI (`.github/workflows/build.yml`) tests on Linux + Windows and builds the Inno Setup installer (`installer/greenline.iss`); a `v*` tag publishes a GitHub release. Bump `Cargo.toml` and `greenline.rc` versions together. Windows builds link the CRT statically (`.cargo/config.toml`).
- Annotations are stored in page-local *view points* (displayed page, y down). `annot::Annot::prims()` is the single geometry source for both the screen painter (`app.rs`) and the flattened export (`render.rs::export`), so keep them in sync through prims, not separate drawing code.
- Export maps view→PDF user space with PDFium's own device↔page transform (`ViewToUser`), so /Rotate and CropBox are handled; covered by `export_lands_in_view_coordinates`.
- Stamps (`stamps.rs`): imported PNG/JPEG seals and signatures are stored by content hash in `<data dir>/images/` (opaque scans get white knocked out, size capped) and listed in `stamps.json`; `Kind::Image` refers to the stored name, drawn via `Prim::Image` (textures on screen, PDFium image objects downsampled to 600 dpi on export). `Annot::group` ties markups on one page together; "Copy to pages" offsets from the nearest page corner.
- Export modes (`render::ExportMode`): Flatten burns prims into page content; Editable writes one Stamp annotation per markup whose appearance is the same prims (`emit_prims` targets either). Existing PDF annotations are never flattened (PDFium's flatten resized pages and dropped comments).
- Renders come in three layers (`render::Layer`): Base (whole page, power-of-two scale), Patch (sharp visible region after the view settles), Thumb (sidebar/overview). The worker drops queued renders for pages no longer in `Keep`.
- Look (`theme.rs`): CopelandBEC brand colours (#446904 primary green, #6B9A1E, #E8F0DE, #444343) as egui light and dark visuals, following the system by default with a choice in F1 (`Prefs::theme`); UI text in bundled Montserrat (OFL, `assets/fonts`). Markup text stays on the Helvetica-metric `helv` family. Markups default to Copeland medium green #6B9A1E (`COLORS[0]`); the thumbnails, markups and stamps panes sit on a shaded panel in light mode (`theme::sheets`); canvas selection stays blue so it shows against green markups.
- PDFium is single-threaded here: in the app, everything touching it runs on the worker thread in `render.rs`. The command line and the tests share one process-wide binding (`pdf::pdfium()`); PDFium can be bound only once per process.
- Crate layout: `src/lib.rs` holds the modules. `src/main.rs` is the app (Windows GUI subsystem), and `src/bin/greenline-cli.rs` is the console command line for agents (`cli.rs`). The command line reads with `pdf.rs` (text runs, vector segments, `snap`, all in view points) and takes markups as JSON ops (`ops.rs`, whose reference `greenline-cli ops` prints). The agent guide is `docs/agents.md`, printed by `greenline-cli guide`; keep it in step with the commands.
- Agents never write the markups file: `greenline-cli apply` adds a batch to `<markups file>.proposals.json` (`proposals.rs`, under its own lock), and the reviewer accepts or rejects it in the app.
- Measuring (`measure.rs`): scales per page or region in real inches per view point, saved in the markups file. `Kind::Measure` carries its value text, refreshed by `measure::relabel`, so it draws through prims like everything else.
- Markups autosave to `<data dir>/<stem>-<fnv hash of path>.json` (`~/.local/share/greenline` or `%APPDATA%\Greenline`) plus `prefs.json`; the source PDF is never modified.
- Open source (MIT OR Apache-2.0, Copeland Building Envelope Consulting, Inc.) at github.com/CopelandBEC/greenline; issues are off and unsolicited pull requests are not accepted (see README). After dependency changes, rerun `scripts/third-party-licenses.sh` (cargo-about; config `about.toml`, template `about.hbs`) so the installer's `THIRD-PARTY-LICENSES.html` stays current.
- Tests: `cargo test` (`tests/cli.rs` runs `greenline-cli` as its own process with a throwaway data folder). Real-file export check: `GREENLINE_SAMPLE=/path.pdf cargo test --release -- --ignored --nocapture`.
